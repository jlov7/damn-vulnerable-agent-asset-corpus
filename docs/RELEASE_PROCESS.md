# Release Process

This document is the publication checklist for a DVAAC release.

## Pre-Release Gates

Run from the repository root:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r runner/requirements.txt
pip install -r runner/requirements-dev.txt
make verify
make pytest-safety
make write-signed
```

Then validate citation metadata:

```bash
cffconvert --validate --infile CITATION.cff
```

## Required Review Evidence

Before publishing:

- save the full `make verify` output;
- save the full `make pytest-safety` output;
- attach `dist/signed-aac/*.json`;
- attach `dist/signed-aac/SHA256SUMS`;
- run at least one negative tamper test by corrupting a copied evidence file and confirming the runner exits nonzero.

## GitHub Release Artifacts

Attach:

- source archive generated by GitHub;
- `signed-aac-vX.Y.Z.tar.gz`;
- `SHA256SUMS`;
- release notes summarizing fixture count, AAC compatibility, and known limits.

## Zenodo

After the GitHub release is final, archive the release on Zenodo and update:

- `CITATION.cff` if a DOI is assigned before tagging;
- README citation text in the next patch release if the DOI is assigned after tagging.

## Versioning

Use semantic versioning for corpus releases:

- patch: runner hardening, docs corrections, digest regeneration with no fixture semantics change;
- minor: added fixtures or changed expected scanner outputs;
- major: incompatible manifest/schema or AAC compatibility changes.
