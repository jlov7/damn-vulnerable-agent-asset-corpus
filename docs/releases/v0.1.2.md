# DVAAC v0.1.2

Patch release for public packaging cleanup. This release supersedes `v0.1.1`.

## What changed

- Removed an internal adversarial review prompt from the public repository tree.
- Kept fixture semantics unchanged from `v0.1.1`.
- Bumped corpus, scorecard, schema `$id`, mapping, and citation metadata to `0.1.2`.

## Compatibility

- DVAAC corpus version: `0.1.2`
- AAC verifier: `v0.2-candidate.5`
- AAC commit: `1fd8f644f55195b5dc90a81896b1bbdec3d9daee`

## Release artifacts

Attached artifacts:

- `signed-aac-v0.1.2.tar.gz`
- `signed-aac-v0.1.2.tar.gz.sha256`
- `RELEASE-MANIFEST.json`
- `SHA256SUMS`

The signed AAC artifacts are generated from checked-in templates by `make write-signed`. The tarball includes 16 demo-signed AACs plus a `release-metadata/` subtree containing the corpus manifest, scorecard template, and schemas bound by `RELEASE-MANIFEST.json` and `SHA256SUMS`. The release manifest is signed with the AAC demo key as a reproducibility and artifact-binding check. The demo key is not an issuer-trust anchor.

## Verification

Expected local gate:

```bash
make verify
make pytest-safety
make write-signed
uvx --from cffconvert cffconvert --validate --infile CITATION.cff
```

Expected final conformance line:

```text
DVAAC: all fixtures conform.
```

## Known limits

- The `v0.1.2` Zenodo DOI is pending until Zenodo archives this release.
- Fixtures 01-03 use `runwright.skills.release`; fixtures 04-16 use `aac.core`.
- DVAAC is a benchmark corpus, not a scanner, vulnerability database, or statistical safety guarantee.
- Demo-key signatures prove verifier plumbing and reproducibility, not author identity.
