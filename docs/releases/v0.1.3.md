# DVAAC v0.1.3

Signed provenance refresh for the Damn Vulnerable Agent Asset Corpus. This release supersedes the unsigned lightweight `v0.1.2` tag without rewriting public history.

## What changed

- Pinned DVAAC to AAC `v0.2-candidate.6`.
- Updated the AAC verifier commit to `a51c7bd4a2de326333b149ad321785a276376cfa`.
- Kept fixture semantics unchanged from `v0.1.2`.
- Aligned citation metadata with the maintainer's ORCID identity.

## Compatibility

- DVAAC corpus version: `0.1.3`
- AAC verifier: `v0.2-candidate.6`
- AAC commit: `a51c7bd4a2de326333b149ad321785a276376cfa`
- Zenodo DOI: pending after GitHub Release archival

## Release Artifacts

Attached artifacts:

- `signed-aac-v0.1.3.tar.gz`
- `signed-aac-v0.1.3.tar.gz.sha256`
- `RELEASE-MANIFEST.json`
- `SHA256SUMS`

The signed AAC artifacts are generated from checked-in templates by `make write-signed`. The tarball includes 16 demo-signed AACs plus a `release-metadata/` subtree containing the corpus manifest, scorecard template, and schemas bound by `RELEASE-MANIFEST.json` and `SHA256SUMS`. The release manifest is signed with the AAC demo key as a reproducibility and artifact-binding check. The demo key is not an issuer-trust anchor.

## Verification

Expected local gate:

```bash
make verify
make pytest-safety
make write-signed
uvx --from cffconvert cffconvert --validate --infile CITATION.cff
```

Expected final conformance line:

```text
DVAAC: all fixtures conform.
```

## Known Limits

- Fixtures 01-03 use `runwright.skills.release`; fixtures 04-16 use `aac.core`.
- DVAAC is a benchmark corpus, not a scanner, vulnerability database, or statistical safety guarantee.
- Demo-key signatures prove verifier plumbing and reproducibility, not author identity.
